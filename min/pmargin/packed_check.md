# Packed BBA5 seed sweep — validation report

Program: `min/pmargin/packed_bba5.ergo` (generated by
`min/pmargin/gen_packed_bba5.py` from `tests/waveform_bba5_seed_0.0.ergo`).
8 folding trajectories (seeds 0.0–7.0) in ONE Ergo program, packed
stage-4 style: per-block state in 1D arrays (`OFF = (B-1)*NRES`), shared
read-only force-field tables (native coords, Go contacts, register
torsions, angle/torsion/hydrophobic params) with local indexing.
MAXFRAME = 48000, quench at 12000 — matching the sequential oracle
(`Protein_Margin/docs/TRANSFERABILITY.md`, `tests/waveform_bba5_seed_*.out`).

## GPU (SPIR-V) report — honest

- Default `--target spirv`: **"No extractable kernels found. Falling
  back to CPU path."** The pair-force loops (steric/hydrophobic/Go) are
  nested scatter loops with FP-order-sensitive velocity RMW — rejected
  ("SCATTER loop: serialized on CPU by default"; inner loops "depend on
  outer loop var"). Kuramoto and Kabsch sums: staged reductions rejected
  (multiple accumulators / integer accumulators). Register torsions: 6
  iterations, "too few for GPU kernel launch". The fallback binary runs
  at CPU speed (2.48 s vs 2.51 s) and agrees with the CPU build (exact
  on settled blocks; seed 1.0 lands on the current-sequential 0.2595).
- `--gpu-fast-math`: the three chain-local force loops (Morse line 242,
  angles line 260, torsions line 291) become extractable as atomic
  scatter kernels — but the build then **fails**: `no lowering for IR op
  'atan2' in kernel` (torsion kernel; ATAN2 has no SPIR-V lowering).
  Compiler gaps to fix before this program can use the GPU: atan2
  lowering, multi-accumulator staged reductions (Kuramoto/Kabsch),
  nested pair-list scatter kernels.

## Timing

CPU: 2.5 s for 8 blocks × 48000 frames (~0.31 s per trajectory) —
compares favorably with the sequential sweep (~0.5 s per 48000-frame
run) thanks to shared-table locality. The packing costs nothing.

## Structural notes (packing mapping + replica-swap feasibility)

What mapped cleanly:
- All dynamics loops: verbatim with `OFF+`-shifted state accesses; loop
  bounds stay LOCAL (NRES), tables stay local-indexed. No restructuring
  needed.
- Kabsch RMSD: verbatim with an `OFFB` subroutine argument (40-iteration
  quaternion power method; no cross-block state).
- Register-torsion bookkeeping: shared read-only tables, uniform
  `FRAME > 1200` gate — trivially block-uniform.
- Kuramoto phase coupling: per-block accumulators reset inside the block
  loop — no interference.
- Shared working scalars are safe because blocks execute sequentially
  within a frame (also true for a future swap step).

Two packing bugs found (both in init/glue, both fixed in the generator):
1. The spliced sequence-params section carried the original
   subroutine's `RETURN`, silently truncating INIT_SHARED before the
   native/contact tables were written (NATIVE_CONTACT all zero → Go
   force off → chains drifted, RMSD grew monotonically). Caught by
   per-force-section velocity probes.
2. `UPDATE_THERMAL(FRAME)` must be called at the END of the frame
   (sequential semantics: frame-1 dynamics run on the BSS 0.0 value).
   Moving it changed little (0.0043 thermal at frame 1) but is required
   for exact reproduction.

Noise/correlation note: SEED enters ONLY the initial coil hash-walk and
the initial THETA phases (verified in `tests/generate_protein_ergo.py`
and the source). The per-frame noise hashes (`SIN((I+1)*7.3 +
FRAME*0.17)` etc.) are seed-INDEPENDENT — the sequential oracle itself
uses identical noise for every seed. Packed blocks therefore share
per-frame noise BY ORACLE DESIGN (local residue index in the hashes);
blocks decorrelate only through different initial conditions. If
independent noise is ever wanted, add a per-block offset to the hash
arguments — but that would break oracle agreement and was not done.

Replica swap (parallel tempering) feasibility: **good**. The packed form
keeps each replica's full state contiguous (`OFF` range); a swap step
needs only a block→slot permutation array applied at force time (or an
exchange of OFF ranges + RMSD/energy bookkeeping, which is already
per-block via COMPUTE_RMSD and the E_NATIVE path). No structural
blockers found; the per-frame block loop is the natural insertion point
(every N frames: compute per-block energies, attempt Metropolis swaps).
The one caveat: everything is sequential CPU today — swaps are free, but
GPU acceleration needs the compiler gaps above closed first.
