## Oracle deltas

Full-grid validation against `results_sweep1.json` (rotor N=8, B=0.25,
all 21 points — sparse-Lanczos complex128 reference): **worst |ΔE0| =
4.8e-11, worst |Δgap| = 4.3e-7** — inside the 1e-4 gap tolerance
everywhere.

Named check points:
- **J = 0.0**: E0 = 0.0000000000, gap = 0.500000 exactly (free rotor).
  The Python-ARPACK-pathology point: power iteration handles it trivially
  (H̃ spectrum [−3, +1], E0 = 0 dominant with ratio 5/6 — converged in
  79+66 iterations). PASS.
- **J = 0.75 / 1.25**: NOT on the 0.1-step grid (grid/oracle mismatch,
  flagged). Ergo neighbors bracket the oracle values: 0.7 → 0.122278,
  0.8 → 0.118139 (oracle 0.75: 0.11955, between ✓); 1.2 → 0.129464,
  1.3 → 0.135076 (oracle 1.25: 0.13220, between ✓).
- **J = 1.0**: 0.120548 vs 0.12055 ✓. **J = 1.5**: 0.147549 vs
  0.14755 ✓. **J = 2.0**: 0.182221 vs 0.18222 ✓ (all within 1e-4).

Convergence: 29–79 iterations/point with warm starts (vs 618 cold at
J=1.0 in Stage 0) — the warm-start chain buys ~5–15× per point, as
advertised in the header note. One outlier: 731 deflated iterations at
J=0.1 (E1/E2 separation smallest there); all well under MAXIT = 20000.

## Timing comparison

- Ergo binary, full 21-point sweep: **0.235 s** wall (11 ms/point).
- Python engine, identical workload (arena matvec + scipy eigsh k=2,
  tol=1e-12, fresh measurement): **1.85 s** → **Ergo ~8× faster**.
  Fairness note: the Python path pays ARPACK/Lanczos bookkeeping and
  numpy dispatch per matvec; the Ergo path is a tight compiled loop with
  warm starts. The comparison is "engine sweep vs compiled sweep", not
  matvec-vs-matvec (the arena matvec itself is already competitive in
  numba).
